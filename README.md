# 输入法增强

**给 Android 输入法注入自定义五笔码表，并解除剪贴板历史条数上限**

![Android](https://img.shields.io/badge/Android-13%2B-3DDC84?logo=android&logoColor=white)
![LSPosed](https://img.shields.io/badge/LSPosed-API%20101%2B-5C6BC0)
![Kotlin](https://img.shields.io/badge/Kotlin-2.2.20-7F52FF?logo=kotlin&logoColor=white)
![License](https://img.shields.io/badge/License-MIT-yellow)

</div>

导入一份 txt 码表（例如「虎码字词」）后，切到五笔键盘即可用自定义编码出字，支持多份码表切换与管理。模块**没有桌面图标**，入口注入在输入法自己的设置页里，控件复用输入法自带样式。

## 支持的输入法

| 输入法                             | 包名                         | 依据版本        | 入口                                                                       |
| ---------------------------------- | ---------------------------- | --------------- | -------------------------------------------------------------------------- |
| 小布输入法（OPPO / 一加 / realme） | `com.oplus.keyboard`         | `1.8.33.17-mkt` | 五笔输入法 → **五笔方案**                                                  |
| 搜狗输入法                         | `com.sohu.inputmethod.sogou` | `20.17.0`       | 五笔设置 → **特殊习惯** → 支持简词                                         |
| 百度输入法                         | `com.baidu.input`            | `13.3.16.2`     | 五笔设置 → **修复五笔方案**（开关）                                        |

小布由模块注入完整的码表导入能力（导入 / 切换 / 重命名 / 删除，最多 3 份，内容相同的按 MD5 自动去重）。

搜狗与百度**本身就能导入自定义五笔方案**，模块只打补丁、不接管它们的码表管理：

- **搜狗**：补一个「支持简词」开关。简词是虎码方案里的 1~3 码高频简码词（属可选项），开关打开时把码表里排序靠前的那个简词挪到候选首位 ——
  **只调序，不造词**，词本身要来自你在搜狗「管理五笔方案」里导入的那份码表。
- **百度**：修它自己的一个时序 bug
  —— 从其它输入法切过来时，已启用的自定义方案不生效（用的是内置方案），要手动切走再切回来才恢复。根因是**核心每次打开时方案键都是内置的 86、且不跨会话保留**，而引擎在开核心那一刻就读了方案，晚一点补推都赶不上；模块挂在
  `IptCoreInterface.openCore` 上，核心一开就把方案写进去。五笔设置页里还有一条**修复五笔方案**开关，关掉就完全不干预。

## 使用

1. 从 [Releases](../../releases) 下载 APK 安装，在 LSPosed 中启用本模块并勾选目标输入法
2. **强行停止该输入法**（或重启手机）—— 模块只在进程启动时注入。
   懒得到设置里点，也可以直接按模块界面顶栏那颗刷新图标（用 root 强停全部已安装输入法）
3. 进入输入法设置页：
   - 小布：五笔输入法 → 五笔方案 → **添加方案…**（长按条目可重命名 / 删除）
   - 搜狗：五笔设置 → 特殊习惯 → **支持简词**
   - 百度：用自带的「管理五笔方案」导入即可；五笔设置页里会多一条「**修复五笔方案**」开关，默认打开（关掉则模块完全不碰百度的方案）
4. 切到五笔键盘，按码表里的编码输入即可

模块自己也有一个入口（桌面图标「输入法增强」，用 Compose + Miuix 写的）：

- 每一行是「**真实应用图标** + 名称 + 注入位置」，行尾一个右箭头表示可点；**点整行**跳到该输入法里
  模块注入条目所在的那一页。三个输入法的注入页都没导出（`exported=false`），普通应用起不来 ——
  走 **root** 的 `su -c am start --user current` 就能起（首次会弹授权框）。
  小布用它自己的 `setting_input_wubi` 深链直达；百度用 `bdinput://openinputsettings` scheme，
  **只能到设置页**（它的「五笔设置」是同一棵偏好树里的一层嵌套 `PreferenceScreen`，没有 Intent 能直达，
  还得再点「输入设置 → 五笔输入」）；
- 列表按**拼音**排序；三个图标都按 alpha 裁掉透明边再补成正方形，大小一致；
- 顶栏右上角那颗刷新图标 = **强停全部已安装的输入法**（让它们重新加载模块）——
  一条 `su -c am force-stop` 停掉，**需要给「输入法增强」授予 root**；停几个只跟装了几个有关，
  跟输入法进程当时在不在跑无关。⚠️ 强停会让系统把当前输入法切走，重选一次即可；
- **模块有没有在 LSPosed 里启用**：标题右上角会挂一个 error 色的「未启用」小上标，并把整页置灰。
  判断用的是 libxposed 的官方 API —— `io.github.libxposed:service` 的 `XposedServiceHelper`：
  模块启用时框架才会通过本 APK 里的 `XposedProvider` 把 binder 递过来，停用立刻断开。
  判据就一条「binder 在不在」，没有超时也没有轮询；不需要 root，也不用改作用域。
- **隐藏桌面图标**：开关桌面图标（`ui.LauncherAlias` 这个 alias）。隐藏后桌面上就没有入口了，
  只能用 `adb shell am start -n com.lookie.opluswubi/.ui.MainActivity` 再打开界面；
  但 **LSPosed 里那颗「打开模块」的 FAB 不受影响** —— 它认的是 `MainActivity` 上那条
  `de.robv.android.xposed.category.MODULE_SETTINGS`，跟桌面图标是两条路。

模块没有额外的设置项：候选注入、选中接管、满码顶屏都是固定行为（顶屏跟随输入法自身的开关状态）。

**回车**：小布输入法下按回车始终上屏你敲的**原始输入**（那串编码），不会上屏候选词；空格与满码顶屏才走码表首选词。

**剪贴板条数上限**：模块会解除输入法自带的剪贴板历史条数上限（小布 500 条、百度 300 条、搜狗 500 条），不再自动删掉旧记录。

## 码表格式

列顺序自动识别，以下写法都支持：

```
的	u          词<TAB>码
u	的          码<TAB>词
的,u  /  的 u    搜狗、百度自定义短语导出
```

编码为 1~6 位纯英文字母（超出会被跳过），`#` 或 `//`
开头的行按注释忽略。内容相同的码表会自动去重（与方案名、文件名无关）。十几万条约 1~3 秒解析完成。

## 已知限制

- 自定义候选固定排在引擎候选之前，不参与引擎的词频学习
- 空格选词 / 自动上屏走的是「替换提交文本」，引擎内部记录仍是它自己那次提交
- 按表中「依据版本」反编译实现；换版本会自动尝试注入并逐项降级，不影响输入法自身启动
- 不替换厂商自带的二进制词库（小布 `wb_down.bin`），自定义码表与内置词库各自独立
- 搜狗的「支持简词」只在候选列表里做置顶，**不会凭空造出码表里没有的词**；简词能否出候选仍取决于搜狗自己的引擎
- 百度只修方案生效的时序问题，不接管码表管理，也不改动它的候选排序；「修复五笔方案」是把当前方案重新下发给引擎，改不了方案本身的内容
- 搜狗适配器目前只按反编译结论实现，真机表现可能与本文有出入，首次使用先看 LSPosed 日志
- **顶屏**：打满码表最长码后，**第五码由模块自己顶屏**
  —— 去掉末位那个码在码表里精确命中就把首选词上屏，并**把触发的那一键按回键盘**（输入法自己那条「五码选首选」只对**它词库里有的码**有效，自定义码表的码它一个候选都没有，所以只能模块代劳；触发键是替你在键盘上重新按一次，引擎按真实按键处理，详见
  [宿主逆向笔记](docs/host-notes.md)）。

出问题先看 LSPosed 日志（TAG
`OplusWubi`），每一步失败都会写明断在哪一环。更多细节：[实现原理与架构](docs/implementation.md) ·
[宿主逆向笔记与验证清单](docs/host-notes.md)

## 源码编译

需要 **JDK 17** 与 Android SDK（`compileSdk 35` / `build-tools 36.0.0`），SDK 路径写在 `local.properties`。

```bash
./gradlew assembleDebug      # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # 产物：app/build/outputs/apk/release/app-release.apk
```

**正式版（release）与 debug 版的差别**：

- 开启 R8 混淆与资源收缩、`debuggable=false`，**不带源文件名与行号表**；
- **不带详细日志**：`XLog.d` / `XLog.i` 的调用点在**编译期**就被消掉（连日志字符串都不进包），开关见
  `app/src/{debug,release}/java/com/lookie/opluswubi/BuildFlags.kt`；只保留 `XLog.w` / `XLog.e` 这类**降级诊断**
  —— 「哪一环没找到、失败在哪一步」照旧会写进 LSPosed 日志。

**正式签名**：把签名信息放在**根目录的 `keystore.properties`**（已 gitignore，不入库）：

```properties
storeFile=release.jks
storePassword=…
keyAlias=opluswubi
keyPassword=…
```

没这个文件时，release 包会退回 debug 签名并在构建时打警告 —— 那种包**只能本机测试，不可发布** （用
`keytool -genkeypair -keystore release.jks -alias opluswubi -keyalg RSA -keysize 2048 -validity 10000`
生成自己的 key 即可）。
